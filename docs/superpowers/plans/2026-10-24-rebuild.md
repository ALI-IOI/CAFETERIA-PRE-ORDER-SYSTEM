# Rebuild of the web pages (same look) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild all eight pages in `web/` as one ordered design system with every state designed, keeping the linen-and-basil look, the API and the C++ server unchanged.

**Architecture:** `web/css/app.css` is rewritten in place as tokens → base → layout → components → states → page rules → motion. Each page's HTML is restructured on that system; the existing scripts keep their API calls and element IDs and only gain the markup for the spec's states, using three new shared helpers in `web/js/api.js`. A new C++ checker (`tools/check_pages.cpp`, ctest `page_rules`) pins the static rules; behaviour in the browser is verified by scripted checks in the browser pane.

**Tech Stack:** HTML, CSS, JavaScript (no libraries, no build step); C++17 + CMake/CTest for the checks; the existing C++ server for running the pages locally.

**Spec:** `docs/superpowers/specs/2026-10-24-rebuild-design.md`

## Global Constraints

- No new features and no server, API or data-structure changes (`src/` is not touched).
- No libraries, frameworks, CDNs or build step; CSP stays `default-src 'self'`; no inline `<script>` bodies, no `style=` attributes in HTML.
- Colours hex only; WCAG AA (4.5:1 text, 3:1 controls); colours exactly: page `#F7F3EC`, panel/bar `#FFFFFF`, line `#E2DACD`, edge `#8A8174`, well `#EFE9DE`, ink `#1F1D1A`, ink-soft `#5E5850`, accent `#1E5B3E`, accent hover `#143F2B`, tint `#E3EDE6`, danger `#A3241C`, danger tint `#F6DED8`. No new hues.
- Type: Cormorant Garamond 600 headings, system sans body; scale 14, 16, 20, 26, 35, up to 58 px (title, fluid); tabular figures for prices, times, counts, IDs.
- Spacing scale 4, 8, 12, 16, 24, 32, 48, 64 px. Square corners, 1 px warm lines, no shadows. 3 px green rule on lead surfaces; dotted leader between dish name and price.
- Widths: phone ≤ 640 px, tablet 641–1000 px, desktop > 1000 px; content ≤ 1180 px; controls ≥ 44 px; no sideways scroll.
- E2E test constraints: `--page: #F7F3EC`, `--bar: #FFFFFF`, `color-scheme: light`, no `prefers-color-scheme`; keep every element ID the scripts use (listed per task); keep "university staff" on `/`, `/login.html`, `/register.html` and "University staff" in `js/api.js`; never "Student or teacher", "University email" (login), "Student & teacher"; no `/staff/` link on public pages; staff scripts stay at `/staff/staff-login.js` and `/staff/staff-portal.js`.
- Wording: sentence case, plain words, no arrows or decorative dots, numbers with units ("৳ 80", "10:00", "3 portions").
- Motion: only colour, opacity, transform; hover/press 120–150 ms; tray count pulse 200 ms; tray line in 180 ms; status tint fade 300 ms; messages fade in 150 ms; nothing on page load or looping; `prefers-reduced-motion: reduce` makes all instant.
- Commits carry no co-author trailer.

Ruling against the spec's "8/8 ctest": this plan adds one test (`page_rules`, Task 1), so done is 9/9.

## Review Focus

1. A long dish or staff-entered item name (e.g. 60 characters) on a 375 px phone: it wraps, the price stays on screen and the leader shrinks, nothing overflows (Task 5, scripted check).
2. The server is unreachable or answers with an error while a list loads: the list shows the error state with a working Try again, never stays on "Loading…" (Tasks 3, 5, 6, 7, scripted check with fetch failing).
3. Reserve all, Cancel or Undo pressed twice quickly: the second press does nothing until the first answer arrives (busy helper, Task 3; scripted double-click check in Tasks 5–7).
4. The cutoff passes while the menu page is open, then the page reloads: closed banner, Add disabled, tray kept but Reserve all disabled (Task 5, using `/api/dev/advance` on the local demo server).
5. No dishes match the search, or no items are available at all: an empty state with the next step, not a blank grid (Task 5).

### Task 3: Shared state helpers

**Files:**
- Modify: `web/js/api.js`

**Interfaces:**
- Produces:
  - `listState(container: Element, kind: "loading"|"empty"|"error"|null, text?: string, onRetry?: () => void): void` — replaces the container's children with a `.state.state--<kind>` paragraph (error adds a "Try again" button calling `onRetry`); `null` removes the state element only.
  - `busy(button: HTMLButtonElement, label: string): () => void` — disables the button, sets `aria-busy="true"`, class `is-busy`, shows `label`; the returned function restores the original label and state. A second call while busy returns a no-op restorer without changing anything.
  - `say(target, text, ok)` keeps its signature; `ok === undefined` now means info (`.msg--info`), `true` success, `false` error, so existing calls keep their meaning except bare two-argument error calls, which callers update to pass `false`.
  - `fillAnnouncement(id)` unchanged.
- Consumes: `el()` (existing).

- [ ] **Step 1:** Add `listState` and `busy`; change `say` as above and update every two-argument call in `web/js/*.js` and `web/staff/*.js` that reports an error to pass `false`.
- [ ] **Step 2: Scripted check in the browser pane** (local demo server running): on `/menu.html`, run `const b=document.createElement('button');b.textContent='Go';document.body.append(b);const r=busy(b,'Going…');const r2=busy(b,'x');[b.disabled,b.textContent,b.getAttribute('aria-busy')]` → `[true,"Going…","true"]`; then `r();[b.disabled,b.textContent]` → `[false,"Go"]`.
